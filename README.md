# jumpdb

`jumpdb` 是一个轻量的 Go 命令行工具，用于研究数据库运维会话的申请流程和本地 TCP 隧道的实现。它复用用户在网页正常登录后取得的授权 Token，申请数据库运维会话，并在本机开放一个与客户端无关的 TCP 隧道。DBX、Navicat、DBeaver、DataGrip、`mysql` 命令行等兼容目标数据库协议的客户端都可以通过它连接。

> **状态：MySQL 主路径已在真实环境跑通，联调未全部完成。** 已实现 `token set`、`connect`、`ui`（本地 Web 控制页）、权限受限配置、会话申请、会话激活与本地 TCP 隧道，并已在真实门户和代理上用 DBX 登录成功。控制页已由维护者在真实环境中按验证清单验证通过（2026-11-03，macOS arm64，DBX）。其他客户端、长时间空闲、长查询及 Token 失效提示尚未验证，详见“已知限制”。

## 工作原理

1. 用户在网页正常登录，取得授权 Token 和资源 ID。`jumpdb` 不做网页自动登录。
2. `connect` 先绑定本机端口，再探测门户时间、申请一次初始会话，显示数据库类型和账号；这时还没有连接代理。
3. 每当数据库客户端连接本地端口，`jumpdb` 都会另外申请一次运维会话，并解密连接参数，不复用初始会话。
4. 连上代理服务后，`jumpdb` 先激活该会话，紧接着完成握手，然后双向转发字节。部分资源要求先激活，否则代理不会返回数据库握手包。数据库认证、查询仍由数据库客户端完成。

本地隧道**不是** SSH，也不额外加密流量，请不要把它当作加密隧道。

## 配置与使用

首次运行前准备好网页登录取得的 Token、资源 ID，以及维护者提供的两把协议密钥。不要把它们贴进命令行参数、聊天或日志。

```bash
# 首次隐藏录入门户 HTTPS 地址、传输密钥、数据库密钥及 Token
# 后续执行仅更新 Token
jumpdb token set

# 显式重新录入所有配置
jumpdb token set --configure

# 启动隧道，默认监听 127.0.0.1:9011
jumpdb connect --id 856

# 字符串 ID 和指定本地端口
jumpdb connect --id RESOURCE_ID --port 9012

# 明确保留数字字符串，而不是 JSON 数字
jumpdb connect --id 856 --id-type string

# 仅在确实需要查看密码时使用；要求标准输出为终端
jumpdb connect --id 856 --show-password

# 启动本地 Web 控制页：配置、启动多个隧道并观测连接
jumpdb ui
```

### 录入与存储

- 门户必须是 HTTPS 根地址，不包含账号、查询参数或业务路径。两把密钥按原始字符串录入，分别恰好 16 字节，不是十六进制或 Base64 编码。HTTP 主流程只使用数据库密钥；传输密钥保留在本地配置中，不用于当前 `connect`。
- `token set` 只接受交互终端，全部字段隐藏输入；不接受凭据参数、管道或文件作为输入。按提示逐项录入，Token 只填写值，不含 Cookie 名称。
- 配置默认位于 `~/.config/jumpdb/config.json`；若 `$XDG_CONFIG_HOME` 为绝对路径，则优先使用 `$XDG_CONFIG_HOME/jumpdb/config.json`，未设置、为空或为相对路径时回退默认位置。路径与二进制所在目录及工作目录无关。目录权限 `0700`，文件创建和更新后均为 `0600`，先写同目录临时文件再原子替换。
- 配置是**权限受限的明文文件，不是加密保险库**，请按凭据管理要求保护本机及备份。文件缺失时首次配置；格式损坏、权限不为 `0600` 或文件为符号链接时拒绝读取。先人工检查、修复或备份移走损坏文件，再录入；不会静默重置。
- `Ctrl+C` 或输入结束可取消尚未完成的录入，不保存部分输入。保存只验证本地格式，不验证 Token 有效性。
- 不查找、不读取、不迁移或覆盖 `~/.ssotool_mac_conf.json`。
- 不再读取 macOS 原路径 `~/Library/Application Support/jumpdb/config.json`，也不会自动迁移或删除它。如需沿用，请先确认新位置没有配置，再手动将原文件移动到上述新路径，并保证目录 `0700`、文件 `0600`；也可执行 `jumpdb token set` 在新位置重新录入。旧文件中的凭据需自行妥善处理。

### 资源 ID 与密码

- `--id-type auto` 为默认值：无前导零的十进制非负整数按 JSON 数字发送；其他非空值按字符串发送。数字必须在 int64 范围内，溢出报参数错误，不静默变成字符串。
- `--id 00856` 默认保留字符串；`--id 856 --id-type string` 也保留字符串。Shell 引号不会保留参数类型，`--id "856"` 与 `--id 856` 相同。
- `--id-type number` 强制非负整数，显式接受前导零并转换为数字；例如 `00856` 转为 `856`。
- 默认只显示本地主机、端口、数据库类型和账号，不输出密码、Token、协议密钥、代理地址或会话 ID。类型与账号使用带引号的转义表示，防止控制字符影响终端。
- `--show-password` 明确授权在终端显示**初始会话**的密码，以带引号的 Go 转义表示显示；拒绝输出重定向，不实现自动或显式剪贴板复制。终端录屏、滚动历史仍可能留存密码。
- 后续连接会申请新会话，凭据可能变化；初始会话信息不保证适用于所有后续连接，也不表示会话或 Token 永不过期。

### 状态、失败与退出

- 固定只监听 `127.0.0.1`，端口默认 `9011`，有效范围 `1..65535`；不提供局域网监听开关。
- **本地正在监听**：端口绑定成功；尚未证明会话、代理或数据库可用。
- **初始／客户端会话申请成功**：已申请并解码；不代表连接到代理。
- **代理连接成功／会话激活成功／代理握手成功**：分别表示 TCP 建连、门户确认激活该会话及收到 `success`；均不代表数据库认证、查询成功。
- 参数错误退出 `2`；配置、端口、门户探测、初始会话或隧道运行失败退出 `1`。错误不会回显参数值、服务端原始响应或底层网络错误中的敏感信息。
- 首版采用**失败即停止**：任一客户端的会话申请、代理连接、会话激活或代理握手失败，报告阶段并关闭整个隧道及其他活跃连接，退出 `1`。会话申请或激活失败只提示检查 Token、权限、连接和密钥，不推断具体失效原因。
- 若所有阶段都成功，客户端却在登录时超时，说明问题在握手之后的数据库流上。可以分别抓本地端口和代理端口 `33306` 的包，看登录包停在哪一侧；抓包只看长度，不要导出载荷。
- `Ctrl+C` / `SIGTERM` 正常取消退出 `0`，停止接入、关闭活跃连接并释放端口。代理连接与握手分别有有限超时，进入转发后清除握手期限；数据库协议错误和转发阶段断开不被解析为数据库登录结果。

## Web 控制页（`jumpdb ui`）

```bash
# 在 127.0.0.1 随机端口启动，自动打开浏览器
jumpdb ui

# 不自动打开浏览器，只在终端打印地址
jumpdb ui --no-open
```

- **生命周期**：前台运行，不注册 launchd，也不开机自启。关闭浏览器页面不会停止控制页；`Ctrl+C` / `SIGTERM` 会停止控制页及其启动的全部隧道并释放端口，退出 `0`。纯 CLI 的 `token set`、`connect` 用法不变，可以与控制页同时使用。
- **访问控制**：只监听 `127.0.0.1` 的随机端口。终端打印的地址含本次运行的随机访问令牌，每次运行都不同，请勿分享；自动打开浏览器时，该地址会作为 `open` 命令的参数传入。接口请求必须携带令牌请求头，`Host` 必须与监听地址完全一致（防止 DNS 重绑定）；修改类请求必须来自本页 `Origin` 且为 JSON。页面设置同源 CSP，禁止被嵌入，也不发送 Referer。
- **配置**：语义与 `token set` 一致。首次使用时填写门户地址、两把密钥和 Token；平时只更新 Token；点击“重新配置”时填写全部字段。密钥和 Token 从不回填，只显示“已设置”；门户地址会回填，便于核对。修改门户或密钥前必须先停止所有隧道。配置损坏或权限异常时，页面只报错，不会覆盖原文件。
- **资源**：常用资源保存在同一配置文件的 `resources` 字段，包含资源 ID、ID 类型、本地端口和可选别名，不含凭据；保存后不会自动启动。ID 类型语义与 `--id-type` 相同。
- **隧道**：可以同时运行多个隧道，端口互不相同。启动流程与 `connect` 一致：先绑定端口，再探测门户并申请初始会话，类型不是 MySQL 时拒绝启动。任一客户端连接在会话申请、代理连接、会话激活或代理握手阶段失败，**只停止该隧道**并显示失败阶段，其他隧道照常运行。会话相关的失败会提供“更新 Token”入口，提示不推断具体失效原因。
- **Token 热生效**：每个新的客户端连接都会从磁盘重新读取 Token。在页面上更新 Token，或在另一个终端执行 `token set` 后，下一个新连接即使用新 Token，已建立的连接不受影响。门户地址和密钥在隧道启动时锁定；如果在外部被修改，下一个连接会失败，并提示重启隧道。
- **观测**：每个连接显示接入时间、已通过的阶段、时长、实时上下行字节数，以及结束原因（客户端关闭、上游关闭、隧道停止；后者包括手动停止、因其他连接失败而停止隧道及控制页退出），另有近期事件流水。数据只保存在内存中，每个隧道保留最近 50 个已结束的连接和 200 条事件，进程退出即清空。页面不显示代理地址、会话 ID 或原始错误。
- **密码**：默认隐藏。点击“显示密码”会通过 `POST` 请求获取**初始会话**的密码，可以再次隐藏；隧道停止后清除。不提供复制按钮，需要时请手动选中复制。

## 开发

需要 Go 1.26 或更高版本。

```bash
go build ./...
go test ./...
go test -race ./...
go vet ./...

# macOS 两种架构；交叉编译不等于目标机器运行验证
GOOS=darwin GOARCH=arm64 go build -o /tmp/jumpdb-darwin-arm64 ./cmd/jumpdb
GOOS=darwin GOARCH=amd64 go build -o /tmp/jumpdb-darwin-amd64 ./cmd/jumpdb

# 可选开发 smoke，需要 Python 3；CLI 运行本身不依赖 Python
python3 -I -B scripts/smoke_cli.py /tmp/jumpdb-darwin-arm64
```

本地正式构建与 CI 打包参数一致，产物写入已被 Git 忽略的 `dist/`：

```bash
rm -rf dist && mkdir -p dist
for arch in arm64 amd64; do
  mkdir -p "dist/$arch"
  CGO_ENABLED=0 GOOS=darwin GOARCH=$arch go build -trimpath -o "dist/$arch/jumpdb" ./cmd/jumpdb
  cp README.md "dist/$arch/README.md"
  COPYFILE_DISABLE=1 tar -czf "dist/jumpdb-darwin-$arch.tar.gz" -C "dist/$arch" jumpdb README.md
done
(cd dist && shasum -a 256 jumpdb-darwin-arm64.tar.gz jumpdb-darwin-amd64.tar.gz > SHA256SUMS)
```

## 已知限制

- 真实环境仅验证了 DBX 登录。其他客户端、空闲超过 10 秒、长查询及 Token 失效提示尚未验证；`darwin/amd64` 仅在 CI 的 Intel runner 上通过合成测试，未在 Intel 实机上完成真实联调。
- 会话申请先以空资源列表探测时间，后续每次申请更新时钟偏差；与旧版首次申请不同，业务码 `44` 不自动重试。数字和字符串资源 ID 由调用方明确区分。
- 会话激活只以门户返回 `code == 0` 判定成功，失败即停止隧道。多个客户端同时接入时，其他连接的门户请求可能插在某个连接的激活与握手之间，这种情况是否会让激活失效尚未验证。
- 内置公开中间证书用于补链，仍需链接系统信任根并通过证书校验，已在真实门户上验证可用。该证书有效期至 2027-11-02 12:24:33 UTC；门户换证时须核验并更新证书、重新发布程序。
- 隧道严格消费握手响应的 7 字节 `success`；握手中的长度字节按用户名字节数写入，用户名超过 255 字节时拒绝握手。通过可选阶段通知报告单连接结果，不携带原始错误。Provider 必须响应 context，通知回调应及时返回，否则停止时会等待其退出。
- 控制页与 `token set` 保存配置时，都会先重新读取磁盘再原子替换，以保留对方写入的字段；两个进程在同一瞬间保存时，后写入者生效。保存过资源列表后，旧版本 `jumpdb` 会因为不认识 `resources` 字段而拒绝读取配置。
- 控制页的真实环境流程已用 DBX 验证；多个隧道同时访问门户时，各自的激活与握手之间可能插入其他门户请求，影响同上。
- 下载的二进制文件可能被 macOS Gatekeeper 或企业安全策略拦截。本项目目前没有 Developer ID 签名和公证。
